# SovereignCore — Forge 1.20.1

ماد مدیریت سرور با رابط گرافیکی داخل بازی برای **Minecraft Java 1.20.1، Forge 47.2.x و Java 17**.

این پروژه مود Forge است، نه پلاگین Paper/Spigot. چون رابط اختصاصی و ارتباط شبکهٔ کلاینت/سرور دارد، فایل JAR نهایی باید روی سرور و کلاینت تمام بازیکنان متصل نصب شود.

## وضعیت ساخت و آزمایش

سورس جاوا در این محیط با بررسی کامپایل ایستا و شبیه‌ساز امضای API بررسی شده است. به دلیل نبود امکان دانلود ForgeGradle/Minecraft و اجرای سرور واقعی، JAR واقعی در این محیط ساخته و تست نشده است. گردش‌کار GitHub Actions داخل پروژه ساخت واقعی ForgeGradle، remap فایل تولیدی و آپلود Artifact را انجام می‌دهد. موفقیت Build هم جای تست روی سرور آزمایشی را نمی‌گیرد.

## قابلیت‌های پیاده‌سازی‌شده در سورس

- داشبورد گرافیکی با پنل‌های متناسب با رنک، جست‌وجو، فهرست‌های اسکرول‌شونده، دکمه‌های ثابت، تأیید عملیات حساس و پیام خطا.
- ذخیرهٔ بازیکنان بر اساس UUID و تشخیص نام‌های شناخته‌شده؛ مدیریت آفلاین تا جایی که دادهٔ بازیکن در کش/تاریخچهٔ سرور شناخته شده باشد.
- Homeهای نام‌گذاری‌شده، مدیریت Home بازیکن، Warp شخصی و عمومی و Spawn.
- تلپورت به بازیکن، آوردن بازیکن، تلپورت با مختصات و ابعاد مختلف.
- `/tpa`، `/tpaccept` و `/tpdeny` همراه محدودیت تعداد در ساعت و Cooldown.
- رنک‌های Owner، Admin، Moderator، VIP، Builder، Member و رنک‌های سفارشی.
- Rank Editor برای نام نمایشی، رنگ، نماد، توضیحات، اولویت، رنک والد، محدودیت Home/Warp/TPA، Cooldown و مجوزها.
- امکان چند رنک برای هر بازیکن، ارث‌بری مجوزها و Override صریح مجاز/غیرمجاز.
- محدودیت مستقل هر بازیکن برای Home، Warp شخصی، درخواست TPA در ساعت و Cooldown؛ مقدار `inherit` برای برگشت به تنظیمات رنک و `-1` برای نامحدود.
- ابزارهای بازیکن: Heal، Feed، Gamemode، پرواز، آسیب‌ناپذیری، Freeze/Unfreeze، پاک‌کردن افکت/XP، مشاهده و حذف آیتم‌های اینونتوری/اندرچست و دادن آیتم.
- مدیریت Ban/Pardon استاندارد ماینکرافت، Pardon IP، Kick و مدیریت OP/DEOP با محافظت دسترسی vanilla level 4.
- Audit log، بکاپ خودکار `.bak` و بکاپ دستی/بازیابی دادهٔ SovereignCore.
- اعتبارسنجی مجوز سمت سرور برای تمام عملیات؛ مخفی بودن یک دکمه به‌تنهایی به‌عنوان امنیت در نظر گرفته نشده است.

## ساخت JAR با GitHub (بدون نصب Gradle روی کامپیوتر)

۱. ZIP پروژه را دانلود و استخراج کن.

۲. یک repository در GitHub بساز.

۳. **محتویات داخل پوشه** را در ریشهٔ مخزن آپلود کن؛ فقط ZIP یا یک پوشهٔ اضافی حاوی کل پروژه را آپلود نکن. در ریشه باید `build.gradle`، `settings.gradle`، `src/` و `.github/workflows/build.yml` دیده شوند.

۴. پوشهٔ مخفی `.github` و زیرپوشهٔ `workflows` باید هم آپلود شوند. در Windows File Explorer از View → Show → Hidden items استفاده کن.

۵. روی `Commit changes` بزن.

۶. زبانهٔ **Actions** را باز کن. Workflow با نام `Build SovereignCore Forge 1.20.1` بعد از Push به `main` یا `master` شروع می‌شود؛ همچنین می‌توانی آن را باز کنی و `Run workflow` بزنی.

۷. اگر ساخت موفق بود، اجرای سبزرنگ را باز کن و از بخش **Artifacts**، فایل `SovereignCore-Forge-1.20.1-JAR` را دانلود کن. GitHub آن را در قالب ZIP می‌دهد؛ استخراج کن تا فایل JAR داخلش باشد.

۸. همان JAR را داخل پوشهٔ `mods` سرور Forge 1.20.1 و تمام کلاینت‌های متصل قرار بده و همه را دوباره اجرا کن.

اگر Workflow در Actions دیده نشد، در مخزن از **Add file → Create new file** استفاده کن؛ مسیر فایل را دقیقاً `.github/workflows/build.yml` بنویس و محتوای `BUILD_WORKFLOW_TEMPLATE.yml` را در آن کپی کن. سپس Commit کن و دوباره به Actions برو.

## فرمان‌ها

- `/sc` و `/manager` — بازکردن داشبورد
- `/sethome [name]`، `/home [name]`، `/homes`، `/delhome <name>`
- `/setwarp <name>`، `/warp [name]`، `/warps`، `/delwarp <name>`
- `/setspawn`، `/spawn`
- `/tpa <player>`، `/tpaccept`، `/tpdeny`
- `/sctp <player>` — تلپورت مدیریتی با بررسی دسترسی
- `/sc rank <player> <rank>` — تغییر رنک با بررسی دسترسی
- `/sc reload` — بارگذاری مجدد داده‌ها؛ نیازمند vanilla permission level 4

## محل داده و بکاپ

داده‌ها در `<world>/data/sovereigncore.properties` ذخیره می‌شوند. پیش از ذخیره‌ها بکاپ خودکار `sovereigncore.properties.bak` به‌روزرسانی می‌شود و از بخش Settings می‌توان بکاپ دستی `sovereigncore-manual-backup.properties` ساخت یا بازیابی کرد. پیش از تست Restore یا استفاده روی سرور اصلی، از کل دنیا/سرور بکاپ بگیر.

## محدودیت‌های فعلی

- ساخت واقعی ForgeGradle و اجرای کلاینت/سرور واقعی باید توسط GitHub Actions و سپس سرور آزمایشی تأیید شود؛ در این محیط وابستگی‌های Forge در دسترس نبودند.
- عملیات زنده مثل موجودی، حرکت، Heal/Feed، Gamemode و Freeze به بازیکن آنلاین نیاز دارند. مدیریت آفلاین رنک و محدودیت تنها وقتی ممکن است که UUID از کش یا سابقهٔ ذخیره‌شده قابل‌شناسایی باشد.
- سیستم مجوز SovereignCore جایگزین سیستم دسترسی تمام مودهای دیگر Forge نیست.
- پیش از استفاده عمومی، روی یک دنیای آزمایشی کار کن و بکاپ داشته باش.
